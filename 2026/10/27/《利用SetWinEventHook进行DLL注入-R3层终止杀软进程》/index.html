这项技术利用了 SetWinEventHook 这个 API 来实现，该 API 原本是用于实现无障碍功能的。它的使用方式与 SetWindowsHookEx 类似：你无需手动向目标进程写入任何数据。只需注册一些用户界面事件，将 DLL 交给 Windows 系统，系统会自动将该 DLL 加载到触发这些事件的进程中。

简单介绍

SetWinEventHook 原本是辅助功能（Accessibility） API，屏幕阅读器用它订阅 UI 事件。
但当它和 WINEVENT_INCONTEXT 标志、一个 DLL 模块一起使用时，就变成了一种 DLL 注入手段：

  • 注入器不打开目标进程句柄，不写内存，不创建远程线程；
  • 只需要把 DLL 在自己进程里 LoadLibrary 一次，拿到模块句柄和导出函数地址；
  • 剩下的加载和执行，由 user32 自己在目标进程里完成；
  • 触发条件是：目标进程自己的线程产生一个 UI 事件。

WinEvent 是什么

Windows 的 UI（窗口、菜单、控件）发生变化时，user32 会产生“WinEvent”，例如：

事件 值 含义
EVENT_SYSTEM_FOREGROUND 0x0003 前台窗口切换
EVENT_OBJECT_CREATE 0x8000 对象创建
EVENT_OBJECT_SHOW 0x8002 对象显示
EVENT_OBJECT_HIDE 0x8003 对象隐藏
EVENT_OBJECT_LOCATIONCHANGE 0x800B 位置/大小变化
EVENT_OBJECT_NAMECHANGE 0x800C 名称/标题变化

这些事件是通过 NotifyWinEvent 从用户态线程发出的，屏幕阅读器、自动化工具靠订阅它们
来感知界面变化。

SetWinEventHook 的两种投递方式

关键只有 dwFlags 一个参数：*

模式 行为 是否注入
WINEVENT_OUTOFCONTEXT 事件被编组回调用进程，通过隐藏窗口 + 消息队列投递。调用线程必须有消息泵（GetMessage + DispatchMessage） ❌ 不注入
WINEVENT_INCONTEXT 回调必须在 DLL 里；系统把 DLL 加载进“产生事件的那个进程”，并在那里调用回调 ✅ 就是注入
